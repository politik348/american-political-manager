# P1 R3: review-gated runtime integration

P1 acquisition candidates are deliberately separate from `data/p1-approved.json`. Promote only after reviewing the exact file, rights, identity, date and individual-portrait composition. Copy the candidate record with status approved and review fields identity, rights, individualPortrait (true) and evidence (specific review record). Never use an invented QID or approval. Runtime accepts exact IDs and reviewed aliases; conflicting QIDs are suppressed. Existing bundled and scene-approved photographs take precedence. New assets are visible in the shared card/profile renderer and, after answering, archive scenes; the notebook uses the reviewed local image if no old photo is approved. Photo Credits appears on People. The service worker shell cache is advanced. The unit tests verify gate, path, conflict, credit and real bytes for approved entries; an empty list is NOT evidence of successful new portrait rendering.
